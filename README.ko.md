# Inference Lab

[English](README.md) | 한국어

Inference Lab은 RTX 5080 16GB에서 로컬 LLM의 실행 호환성, 저정밀 연산의 전체 호출 비용, 모델 답변의 변화를 비교하는 추론 평가 프로젝트입니다. 재현 가능한 사례와 함께 결과를 다시 계산하고 개별 근거를 살펴보는 도구를 제공합니다. 기존 모델과 커널을 바탕으로 비교 조건을 통제하고, 실패를 보존하며, 측정으로 설명하는 평가 체계를 구현했습니다. 보고서를 읽거나 저장된 결과를 탐색하는 데 GPU는 필요하지 않습니다.

[사례 안내](docs/ko/CASEBOOK.md) · [결과 직접 보기](docs/ko/GETTING_STARTED.md) · [구현과 기여](docs/ko/PORTFOLIO.md)

## 왜 구분해서 비교하는가

커널이 빠른 것, 데이터 변환까지 포함한 호출이 빠른 것, 모델 전체가 빠른 것, 답이 맞는 것은 서로 다른 결과입니다. 비교가 유용하려면 무엇을 측정했는지 먼저 구분해야 합니다. 일곱 사례는 실행 호환성에서 연산 비용과 모델 행동으로 질문을 넓히지만, 모델·입력·프로토콜이 모두 같지는 않습니다. 하나의 연속된 성능 곡선이 아니라 이해를 돕는 읽기 순서이며, 각 사례에 자체 조건·근거·한계가 남아 있습니다.

## 대표 사례: 전체 점수가 비슷해도 개별 답은 같은가

<!-- claims: c006-native c006-readout c006-limits -->
Case006은 attention 연산 한 곳을 바꾸었을 때 개별 선택이 달라지는지 조사합니다. 실행 범위를 제한하는 어댑터로 Qwen3-0.6B의 0부터 센 layer 13에서 프롬프트를 처음 처리하는 prefill attention만 교체했습니다. 다른 층과 이후 토큰 생성은 BF16으로 유지했습니다. B는 원래 BF16 실행인 비교 기준선입니다. A_PUBLIC과 V4는 같은 모델의 attention 연산 한 곳에 적용한 두 저정밀 설정의 이름이며, 모델 가중치는 BF16으로 유지합니다. 검색·비교·코드 과제는 가상 사실에서 정답(gold)을 별도로 계산했고, BF16 모델의 답을 정답으로 삼지 않았습니다.

표준 시나리오 192개에서 BF16 대비 선택이 바뀐 것은 A_PUBLIC **192개 중 5개**, V4 **192개 중 8개**였습니다. 정답으로 바뀐 경우와 다른 오답으로 바뀐 경우가 있었고, 표준셋에서 회귀, 즉 기준선이 맞힌 답을 후보가 틀린 경우는 없었습니다. 그러나 별도로 선정한 스트레스 46개에서는 정답을 잃은 사례가 있었습니다. 두 설정 모두 과제별 가중치를 같게 둔 정답 선택지의 음의 로그우도(NLL) 쌍별 변화 평균에 대해 95% 구간을 구했으며, 그 구간은 0을 포함했습니다. 변화는 후보−BF16이며, 양수는 정답에 부여한 확률이 낮아지는 방향입니다. 이 결과만으로 품질의 동등성을 입증하지는 않습니다. [본실험 결과와 범위 — 기술 원문(영어)](cases/006-attention-decision-stability/README.md).

![표준셋에서 정답에 부여한 점수의 쌍별 변화](cases/006-attention-decision-stability/figures/01_score_changes.png)

*정답 선택지 NLL 변화는 후보−BF16이며, 양수는 정답 확률이 낮아지는 방향입니다. 각 점은 시나리오와 후보의 한 쌍이며, 위 문단의 구간은 과제별 가중치가 같은 쌍별 변화 평균에 대한 것입니다. 축과 라벨은 원래 영어 표기를 유지했으며, 점수 변화와 정답 여부를 구분합니다.*

Readout은 모델 내부 상태를 어휘 점수로 바꾸는 마지막 출력 계산입니다. 사후 진단은 원래 출력 계산(native)과 별도 진단용 출력 계산(shadow)을 구분합니다. 이 진단에서는 원래 표준셋의 모든 선택 변경에 기준 또는 후보의 최고점 동률이 관련돼 있었습니다. 같은 최종 hidden state와 BF16 가중치에 표현된 값을 별도 FP32 출력 head로 계산하자, 후보마다 **192개 중 3개**의 선택 변경이 관측됐으며 새로운 변경도 생겼습니다. 각 후보는 같은 readout 조건의 B와 비교했습니다. 같은 표준 192개와 스트레스 46개를 다시 사용한 진단으로, 새로운 확인 표본이나 개선된 모델의 증거가 아닙니다. [별도 진단의 기존 한국어 설명](cases/006-attention-decision-stability/supplemental/readout-ties-v1/README.ko.md).

근거 탐색기는 정확한 질문, 정답, 선택지 점수와 결과를 연결합니다. 한계도 함께 드러납니다. BF16의 코드 과제 정답은 **15/64**였으며, 별도 구조화 생성에서는 모든 설정의 엄격한 형식 유효율이 **0/24**였습니다. 통제된 실험은 완료됐지만 배포 적합성은 **NOT_ASSESSED**, 즉 평가하지 않은 상태입니다.

## 프로젝트의 기여와 범위

비교 실행 도구, 입력·정답 구성, 실제 경로 검사, 스칼라 재검산, 저장된 근거 탐색기를 구현했습니다. Qwen과 Red Hat AI는 체크포인트를, vLLM·PyTorch·Transformers·SageAttention은 실행 구성요소를 제공합니다. Case001의 guard는 hclsys의 작업이고 EFQ-Softmax는 Han과 공동저자의 방법입니다. [기여와 재사용 안내](docs/ko/PORTFOLIO.md#contribution-and-reuse)에서 원래 출처를 확인할 수 있습니다.

OpenAI Codex가 코드·로컬 검사·분석·문서 작성을 지원했습니다. 별도 계산 경로는 기록의 일관성을 확인하며 외부 제3자의 GPU 재현을 뜻하지 않습니다. 부정 결과를 포함한 특정 장치·과제의 조사이며, 새 양자화 방법·범용 SDK·운영 제품의 실적이 아닙니다. 프로젝트 자료에는 [Apache-2.0](LICENSE)을 적용하고 사례별 고지에 원저자와 해당 라이선스를 보존합니다.
