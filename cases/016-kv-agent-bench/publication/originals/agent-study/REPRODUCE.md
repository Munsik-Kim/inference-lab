# Reproduce the recorded results

The CPU path uses Python's standard library. It does not load a model, Torch or Transformers, connect to a server, or download anything. Run from this case directory, with a fresh output root:

```bash
CASE016_CHECK_ROOT="$(mktemp -d /tmp/case016-cpu.XXXXXX)"
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src python3 -B -m kv_agent_bench.cli validate --case .
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src python3 -B -m unittest discover -s tests -v
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src python3 -B -m unittest discover -s publication/tests -v
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src python3 -B -m kv_agent_bench.cli oracle-check --case . --output "$CASE016_CHECK_ROOT/oracle"
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src python3 -B -m kv_agent_bench.cli audit --tasks data/tasks.json --results results/p1_r1 --output "$CASE016_CHECK_ROOT/replay"
python3 -B scripts/audit_results.py --output "$CASE016_CHECK_ROOT/independent"
python3 -B scripts/verify_sources.py --output "$CASE016_CHECK_ROOT/source-views"
```

`oracle-check` executes synthetic gold traces, including the future EVAL fixtures; it is not an LLM measurement. `audit` rebuilds tool execution from recorded SSE and fresh fixtures. `scripts/audit_results.py` separately reconstructs SSE/token counts, request caps, termination and paired tables and checks two scalar endpoint implementations. The saved success booleans are compared only after reconstruction. Without the private tokenizer this does not independently decode token IDs back to text; without weights/logits it does not reproduce GPU inference.

The standalone local pages are [Korean](demo/ko.html) and [English](demo/en.html). To regenerate a display without changing the original evidence, copy the case to a new scratch directory first, then use the implemented `render` subcommand on that copy. Its CLI is available through `PYTHONPATH=src python3 -B -m kv_agent_bench.cli --help`.

## The actual GPU execution path

GPU work requires the existing read-only Qwen snapshot, the dedicated isolated environment and a private runtime receipt. These are not included in the archive. The executed entry points were:

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src "$CASE016_GPU_PYTHON" -B -m kv_agent_bench.cli run --case . --runtime "$CASE016_PRIVATE_RUNTIME" --stage p0
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src "$CASE016_GPU_PYTHON" -B -m kv_agent_bench.cli run --case . --runtime "$CASE016_PRIVATE_RUNTIME" --stage p1
```

`CASE016_GPU_PYTHON` must identify the isolated Python3.12 environment; `CASE016_PRIVATE_RUNTIME` is the actual runtime JSON. Its fields are `python`, `snapshot`, `private_root`, `prepared_root`, `p0_run_id`, `p1_run_id`, `pool_bytes`, `p1_max_model_len`, `p1_kvs`, `source_commit`. The author’s P0 repair attempts additionally use explicit `p0_kvs`/`p0_reuse_results` and diagnostics fields; those reuse choices are evidence history, not defaults for a new run. A fresh reproduction must use new result and fixture paths, run its own support/instrumentation checks, and provide matching gates. Do not overwrite these archived cells or manually mark support gates PASS.

Dependencies are recorded in [resolved-lock.txt](provenance/resolved-lock.txt), [environment.json](provenance/environment.json), and the private pip reports. The vLLM wheel is pinned to0.32.0; its relevant installed source files match official tag `5df63a7`. FlashInfer's official download command installs prebuilt kernels. CUDA compiler/CRT/NVVM were aligned to13.0.88 inside this new environment only; the driver and existing environments were not changed. Setup failures and amendments remain in the evidence.

The model is `Qwen/Qwen3-4B-Instruct-2507@cdbee75f17c01a7cc42f958dc650907174af0554`. [model_identity.json](provenance/model_identity.json) contains actual local hashes for all12 snapshot files, including all weight shards. These are local identities, not a comparison against an independently obtained official weight digest.

Before a new GPU run, verify the snapshot, engine/dependency versions, offline loading, all36 layer cache dtypes, actual pool/capacity and input IDs. Preserve prefix caching OFF, eager/common scheduling, BF16 weights, parser, no schema/name constraints, EOS and all registered budgets. The installed official CLI help was inspected; no old Case009 runner or fixed-output settings are inherited. Only the owned loopback server on8152 may be stopped.

P2/P3, fresh EVAL model execution and remote publication are not part of this run. Model weights, full KV pages, virtual environments, large profiles and private paths are excluded from the review archive.

The final styled review pages are generated by `python3 -B scripts/render_review.py --case <FRESH_CASE_COPY>`. This display-only wrapper keeps the frozen minimal renderer unchanged and adds the DIOVA palette, explanations, figures and filters. Source views verify all11 historical freezes; the current35 P1 execution files retain their original bytes.
