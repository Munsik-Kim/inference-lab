1. 무엇을 구현했고 무엇이 확인됐나
비공개 blockfmt 없이 실행하는 INT4 solver, 실제 nibble artifact 저장·재로딩, 전체 모델 GPU 품질 runner, 장문 DEV scorer와 로컬 도구 harness를 구현했다. Qwen0.6B와4B의 모든 transformer projection에 RTN·D16·D4를 적용하고 BF16과 같은 입력으로 비교했다.
0.6B에서는 D16의 PPL이 RTN보다 작았다. 4B에서는 weight MSE와 KL이 작아졌어도 PPL과 자유 agent 성공률은 좋아지지 않았다. 저장한 가중치의 오차, 문장 확률 점수, 도구를 올바르게 실행하는 능력은 서로 다른 지표였다.

7. 공개 packed probe: 전체 모델 대응 미통과
기존 vLLM0.29.0의 _C.gptq_marlin_repack/marlin_gemm을 사용하고 SM120의 실제 marlin::Marlin CUDA kernel을 profiler로 기록했다. packed INT4 weights에서 BF16 tensor-core MMA로 fused unpack하는 W4A16이며, native INT4 MMA/W4A4/저자의 Nunchaku 경로는 아니다.
최종 precision-aligned probe: GEMM 상대RMSE 0.003078, 한 block 0.005673 PASS.32token 전체모델 상대RMSE 0.026054 > 사전 기준0.02로 BLOCKED. greedy4token suffix는 같았지만 forward argmax 차이 0.031250였다.
초기2.5533%, BF16 scale 대응 dense 진단2.2598%, reduction flag를 본 품질runner에 맞춘 마지막2.6054% 모두 기준 미통과다. scale 반올림과 kernel 산술 차이가 남아 있으며 원인을 하나로 확정하지 않는다. 기준을 넓히지 않고 이전 실패를 보존했다.
옛 probe01/02는 receipt를 기록한 handler 때문에 exit0였어도 semantic status는 BLOCKED다. 현재 CLI는 BLOCKED에서exit1이며 마지막probe03 실제exit1을 기록했다. exit0을GPU PASS로 세지 않는다.
32input/4output·3repeat의 실제 wall/allocated/reserved는 각 receipt에 있다. 수치 대응 gate 미통과와 cold/warm 변동 때문에 이를 유효한 serving speedup이나 capacity gain으로 보고하지 않는다.
