# Case021 통합 설명 — 저장 표현, GPU 실행, 후속 계산을 구분하기

**단일항은 같았지만 실제 값의 결합에서 차이가 남았습니다.** 두 q_proj와 기존 DEV2문서의 고정 마스크에 한정한 P5 결과입니다. 같은 INT4 artifact를 사용해도, 가중치를 어떤 숫자로 복원하고 어떤 GPU 경로로 계산하는지, 이후 계산이 오차에 얼마나 민감한지는 서로 다른 질문입니다.

| 질문 | 비교와 실제 근거 | 해석 |
|---|---|---|
| 복원 표현을 바꾸면? | D0 `(codes×gamma)×alpha_inv` 대 D1의 BF16 combined scale·BF16 weight | 곱셈 재결합과 scale/weight 반올림 위치가 함께 달라짐 |
| 표현을 맞춘 뒤 실행은? | D1 대 실제 Marlin P; P4 실제 입력 차이, P5 단일항 일치·여러 항 차이 | 국소 실행 차이는 지지되지만 내부 누적/scale 처리의 단일 원인은 미분리 |
| 중간 정밀도를 높이면? | 동일 Q/K 입력과 native cos/sin에 R0/R1; P4의 FP64 참조 및 gap 분해 | 개별 참조 정확도와 경로 간 일치도는 별개 |

D0도 원 미압축 checkpoint가 아니라 D16 artifact의 dense 참조입니다. D1/P는 같은 code와 BF16 scale, 입력에 한 번만 적용한 beta를 공유합니다. R1은 Q/K norm–RoPE의 중간값을 FP32로 유지한 뒤 최종 Q/K를 BF16로 넘기는 개입이며 모델 전체 FP32 변경이 아닙니다. 공통 R0가 이미 같으므로 이 결과를 RL 실행 스택 정렬의 재현으로 부르지 않습니다.

기존 EVAL24의512길이·16위치 full-vocabulary KL은 E0=0.0006952504144, E1=0.0007815328033, delta=-0.0000862823889입니다. 문서 단위95% 구간 [-0.0002068221560, 0.0000390900519]이0을 포함하여 **INCONCLUSIVE**입니다. P5는 이 모델 출력을 새로 만들거나 새 확인 데이터로 바꾸지 않았습니다. 원32-token D0–P 약0.02605433은 역사적0.02 gate 밖이라는 기록도 유지합니다.

P4에서 EVAL 국소96조합의 양쪽 개별 FP64 참조 오차 합은 모두 줄었지만, 경로 gap은34증가/57감소/5동일이었습니다. P5A는 증가34개를 ΔN/ΔC의13/17/4로 다시 구분했습니다. 정확도가 좋아져도 과거 오차의 상쇄가 약해져 두 실행 차이가 커질 수 있다는 국소 설명이며, 전체 모델 KL의 원인을 다 설명하는 것은 아닙니다.

P5B의 단일항 두 실행은 모두 A와 맞았고, A/B가 다른406,626좌표에서도 동일했습니다. P5C는 K1·2에서 네 조합 모두 같았고 K8 또는64부터 차이가 관측됐습니다. K1024 원 입력/출력은 P4와 일치했습니다. 이후 새 K·seed·모델·kernel 변경 없이 GPU 진단을 종료했습니다.
