## 환경과 operator 계약

실제 환경은 Python3.12.14, NumPy2.3.5, Torch2.13.0+cu130, CUDA runtime13.0, driver621.01, NVIDIA RTX5080 SM12.0, WSL2 Ubuntu / Linux5.15.167.4다. 실제 import 경로, 논리 CPU16개의 affinity와 telemetry를 worker별로 저장했다. 기존 runtime을 읽기 전용으로 재사용했으며 독립 clean environment 검증으로 부르지 않는다. 그림은 기존 `ai_lab`의 Python3.10.19 / NumPy2.2.6 / Matplotlib3.10.8로 만들었다. 설치한 package는 없다.

eager·inference_mode·기본 stream을 사용한다. 출력은 raw unscaled BF16 `[M,4096]`이며 layer 순서를 유지하는 `[M,16,256]`과 같다. ID는 GPU int64이고 timed 출력도 GPU에 남는다. `install_compact_ple`의 scale은 적용하지 않았다. TF32=false, FP16/BF16 reduced-precision reduction=false, FP16 accumulation=false다. runtime 기본 reduction flag는 true였고 원 Case의 명시적 FP32 누적 정책을 유지했다. OMP/MKL/OPENBLAS/Torch thread는1이다. CPU affinity는 관측했으며 단일 core로 고정하지 않았다. GPU clock·전력 설정은 바꾸지 않았다. allocator/backend/interop thread와 실제 값은 raw에 있다.

A는 공식 decoder를 고정256행 chunk로 호출해 전체 BF16 table을 만든다. 지연시간 전용 worker에는 A와 B/C/S가 공유하는 compact module 하나가 공존한다. A 구축용 임시 decoder를 제거한 뒤 공유 compact를 로드한다. 모든 방법이 같은 상태를 쓰며 이 공존 메모리는 method-isolated 메모리 근거로 쓰지 않는다. C는 매번 unique/inverse를 계산한다. S는 ID 정렬→M행 전체 복원→inverse permutation으로 원 순서 복귀를 수행하고 Z32/M2048/U2048에만 둔다.

## H / D / E 계측 설계

core는 입력3개×fresh process6개=18 worker, S를 포함해60 method-block이다. width는 폭2개×입력2개×process3개=12 worker,36 method-block이다. 합계30 worker/96 method-block이다. 방법마다 최초20회와 각 pass 시작20회 warm-up을 한다. core의 pass6순열과 width의 cyclic Latin 순서로 pass 순서를 균형화했다. 본 pass의 방법 순서는 ABC6순열 또는 ABCS24순열 전체를 고정 seed로 shuffle한 cycle/start로 균등 반복한다.

H는 방법별120 round·K1로 pre-sync→host 시작→fn→device synchronize→host 종료다. D는48 round·K1로 host 시작→event 시작→fn→event 종료→end-event synchronize→host 종료이며 host에 event 기록/wait가 포함된다. E는24 bracket·공통K16으로 stream elapsed/16이다. 출력은 쌓지 않고 해제한다. timed function 안에 profiler·I/O·로그·telemetry·gc·empty_cache를 넣지 않는다. H/D/E는 별도 pass이고 D만 같은 row에 두 clock을 저장한다. 타이머 일치를 성공 조건으로 두지 않았다.

quantile은 linear 보간이다. trim/winsorize나 느린 표본 제외는 하지 않았다. raw에는 round/rank/order/start/end가 있다. 본 관측 row는 H11520+D4608+E2304=18432개다. D4608행에 두 clock이 있어도 독립 workload를 추가한 것으로 세지 않는다. CSV의 rate는 positions/s와 layer-rows/s이며 event bracket과 동기 host의 범위를 나눴다. LLM tokens/s가 아니다. `round_samples.csv`, `same_call_dual_timer.csv`, `paired_round_comparison.csv`, `paired_block_comparison.csv`에 있다.

## P4A 원 자료 재분석과 메모리 단계

최종 raw90개에서 재계산한 값은 host-median C 승리5/30, event-mean4/30, 공통0/30, 불일치9/30, host 승리 중 U=M3개, 세 block 모두 host 승리한 조건0/10이다. median/median은5/4/1/7, mean/mean은8/4/1/10이었다. 원 별도 pass·K32/8/1 계약은 유지한다. `legacy_statistics.csv`180 clock record는 각100표본의 통계이며 원 표본은 원 파일에 남아 있다. P2 분모90을 P4 method-block96에 더하지 않는다.

원90 worker 모두 baseline에32MiB가 이미 있었다. warm−baseline−module−IDs 잔여는0–952 bytes다. 별도 after-load/output-release endpoint는 저장되지 않았다. 새 memory worker는 A/B/C의 library GEMM 전/후, artifact, 첫 출력, 출력 해제, warm20, module/ID 제거 단계를 관측했다. 제거 후 active32MiB block의 setWorkspaceForHandle/getCurrentCUDABlasHandle C++ stack으로 새 replay의 Torch cuBLAS handle workspace 소유자를 확인했다. 새 endpoint/reserved 이력은 진단이며 기존 timed peak를 대체하지 않는다. Python tensor 열거만으로 소유자를 판정하지 않았다. 단계/stack으로 이 질문에 답했으므로 추가 profile worker는 실행하지 않았고 unique/decode/inverse 내부의 순수 비용을 주장하지 않는다.

## 해석 범위

측정 범위는 RTX 5080 한 대의 eager operator다. 같은 synthetic artifact와 같은 GPU ID를 반복하는 warm-cache 호출이며 raw unscaled BF16의 모든 16 layer를 반환한다. 실제 LLM, 학습된 OPTIC artifact, 언어 품질, TTFT/TPOT, KV 재배분, 서버 동시성은 측정하지 않았다. Z644는 E4B의 latent 폭에 대응할 뿐 V/L/H와 품질을 재현하지 않는다. 파일 cache는 warm일 수 있고 GPU/CPU clock을 고정하지 않았다. WSL의 device 전체 표본은 연속 peak 또는 process별 완전한 attribution이 아니다. P2 isolated 결과와 P4 shared-context 결과는 서로 다른 계약으로 유지한다. block은 process 반복 단위이며 내부 호출을 독립 모델·사용자 과제로 세지 않는다. 전력 표본으로 에너지나 비용을 추정하지 않는다.
