<a id="question"></a>
## 2. Question and terms

A1 asks the model to read a purchase record, multiply item count by price per item, save the total, validate the saved record and return final JSON. order_id identifies the synthetic record; unit_price_minor is the integer price per item; total_minor is the integer total. No shop/payment account is connected.

A checkpoint fixes the messages/tools, received results, actual file state and used budget immediately before the first write response. The two original read/multiply calls are replayed into a fresh fixture, not regenerated by the model. The original 96 episodes /463 requests /378 attempts /368 actual events were replayed on CPU. The selected eight D16 failures stopped at 43–48 tokens with EOS 151645, not the 192-token cap or exhausted budgets. Their original stale BUDGET_EXHAUSTED label and failure verdict remain byte-preserved; PARSE_ERROR is the diagnostic interpretation. Two other historical malformed slots occurred in successful mixed responses, not feedback recovery.

<a id="contract"></a>
## 3. Fixed execution and interventions

Qwen/Qwen3-4B-Instruct-2507 revision cdbee75f17c01a7cc42f958dc650907174af0554; existing BF16/RTN/D16. All 252 saved projections per quantized method retain FP32 beta_inverse transport and BF16 W_pre. Greedy, thinking=False, 192 new tokens, batch 1, SDPA, within-request BF16 KV on, across-turn cache off, logits_to_keep=1, TF32/reduced reduction=False. One resident model at a time.

C0 uses the original request and malformed-only stop. G uses identical messages/tools and an actual decoding mask only on the focal response. All four tools remain selectable; argument fields/types are conditional on the declared name, but IDs and integer values are free, and final validated may be true or false. There are no gold constants/whitelists, forced write, post-hoc JSON repair or parser relaxation. Multiple calls and write→validate are allowed. A complete call dict may end without its closing marker, matching the original parser; incomplete JSON cannot emit EOS. Original unmasked finite-logit/deadline checks run before intentional grammar -inf.

N/E branch from the same genuinely new malformed-only C0. Its raw text remains assistant content; feedback is a user message, not a fake tool result. N: `No tool was executed. Retry the previous response.` E: `PARSE_ERROR: Tool-call JSON could not be parsed. No tool was executed. Retry the previous response.` Only that feedback differs. The model sees only messages/tools; audit fixtures, oracle and other methods' outputs are excluded.

The prefix already costs 2 model calls and 2 tool attempts. Totals remain 8/6, 192 tokens, 24,576 context tokens and 900 seconds; malformed markers consume attempts and the shared new C0 is charged to N/E. The registered conservative common prefix-time debit is retained. No branch receives fresh budgets.

<a id="errors"></a>
## 6. Failure and recovery analysis

G/D16 performed the correct write, received current validation and completed a strict final in all 8 cases. N restarted reading in all 8; seven later write responses remained malformed. In API_V2 A1-06, a read/multiply/write/validate batch exceeded the three remaining tool attempts: the first three ran, the amount was saved correctly, but validation was not executed. A later validation request was still blocked by the tool budget. Those redundant calls are permitted paths, not automatically observation violations. E restarted reads and later failed write serialization in all 8.

The BF16 API_V1 A1-06 validation used a wrong record ID under both C0/G. Correct final file state alone was insufficient. Focal grammar did not repair this later error.

Three G downstream, unmasked slots had extra trailing material accepted by the unchanged first-dict parser. N/E also contain such acceptance. This is not strict whole-document JSON for every response. [Raw cells](results/gpu_r2/cells), [error transitions](results/gpu_r2/diagnostics/error_transitions.json).

<a id="conclusion"></a>
## 8. Conclusion and scope

**Recovery observed:** contract-constrained serialization of the focal response recovered exact arguments and the actual workflow on these selected D16 checkpoints. This supports the output serialization/contract boundary as an effective intervention point here. It does not establish a unique internal cause or a general INT4 defect; RTN already completed 8/8.

N recovered one correct stored state but no completed workflow; E did not add workflow recovery over N. Remaining issues include unmasked write representation, redundant-call budget cost and BF16 validation-ID choice. Historical free-generation failures remain failures.
