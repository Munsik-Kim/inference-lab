# Case015 — 같은 도구, 다른 이름

AI가 사용하는 도구의 이름만 바뀌면, 같은 일을 끝까지 해낼 수 있을까요? 이 연구에서는 조회·계산·저장 기능을 AI에게 제공하고, 기능은 그대로 둔 채 이름 표기만 바꾸어 작업 결과를 비교합니다.

구체적인 예제는 **구매 내역의 총금액을 계산해 기록하는 일**입니다. AI는 구매한 개수와 개당 가격을 조회하고, 둘을 곱한 금액을 저장한 뒤 제대로 기록됐는지 확인해야 합니다. 이 흐름을 실행하고 결과를 다시 검사하는 도구를 구현했습니다.

> **P2 추가 실험:** 합계를 저장하는 호출문이 깨졌던 4비트 모델 D16의 실패 8건을, 같은 조회·계산 결과에서 다시 확인했습니다. 첫 응답의 형식을 도구 계약에 맞게 제한하자 8/8건이 저장·검증·최종 답변까지 완료됐습니다. 중립 재시도와 오류 설명은 각각 0/8건이었고, 중립 재시도 1건은 저장까지만 회복했습니다. 합성 기록 4개 × 이름 표기 2종의 진단이며 기존 P1/A1 점수와 별도로 봅니다.

## AI에게 시킨 일

1. **구매 정보 확인:** 지정된 구매 내역에서 개수와 개당 가격을 읽습니다.
2. **총금액 계산:** 조회 결과를 받은 다음, 곱셈 도구에 두 숫자를 전달합니다.
3. **금액 저장:** 계산 결과를 받은 다음, 해당 구매 내역의 총금액을 수정합니다.
4. **저장 결과 확인:** 올바른 금액인지 확인하는 도구를 실행합니다. 다른 구매 내역은 바꾸면 안 됩니다.
5. **완료 보고:** 확인 결과를 받은 뒤, 구매 ID·총금액·확인 여부를 정해진 형식으로 답합니다.

실제 쇼핑몰과 연결하지 않고 실험용 JSON 파일로 시험했습니다. JSON은 항목 이름과 값을 짝지어 저장하는 텍스트 형식입니다. 초기 요청에는 개수와 가격을 넣지 않았으므로 AI가 조회 도구의 결과를 받아야 합니다. 금액은 소수점 없는 정수 단위로 다룹니다.

## 도구 이름은 어떻게 바꿨나요?

AI가 도구를 이름과 입력값으로 부르는 연결 방식을 API라고 합니다. 여기서는 도구의 이름 표기 두 가지를 **API_V1(원래 이름)**과 **API_V2(바꾼 이름)**로 부릅니다. 예를 들어 구매 내역을 읽는 `read_order`를 `readOrder`로 바꿉니다. 기능·설명·입력값 형식·목록 순서는 같습니다.

## 용어를 읽는 법

| 처음 보는 표현 | 이 사례에서의 뜻 |
|---|---|
| 주문 / order | 구매 내역 한 건. 기록의 `order_id`는 그 내역을 구별하는 ID입니다. |
| 수량 / 단가 | 구매한 개수 / 물건 하나의 가격입니다. |
| 도구 호출 / API | AI가 조회·계산 같은 기능을 이름과 입력값으로 요청하는 방식입니다. API 이름은 그 기능을 부르는 이름입니다. |
| 시나리오 / fixture | 시험할 문제 한 개 / 그 문제에서 사용하는 초기 실험용 파일입니다. |
| episode | 초기 파일에서 시작해 AI가 답을 마칠 때까지의 실행 한 번입니다. |
| 관측 이력 | AI가 다음 응답을 만들기 **전에 이미 받은** 도구 결과입니다. 파일이 바뀌었다는 사실과 구분합니다. |
| 회귀 / 회복 | 이름 변경 전에는 성공했지만 이후 실패 / 이전 실패가 이후 성공으로 바뀐 경우입니다. |

코드의 `quantity`, `unit_price_minor`, `total_minor`는 각각 개수, 정수 단위의 개당 가격, 총금액입니다. 코드·원기록의 필드명은 유지합니다.

## 비교 범위와 실제 결과

비교한 모델은 같은 Qwen3-4B의 세 가지 표현입니다. **BF16**은 원래 16비트 모델, **RTN**은 단순 반올림으로 가중치를 4비트 저장한 기준선, **D16**은 DualQuant 공개 수식 기반으로 가중치를 4비트 저장하고 중간 계산값은 16비트로 유지한 비교 조건입니다. 압축 저장본은 BF16으로 복원해 작업 수행 품질을 측정했습니다.

숫자와 구매 ID가 다른 16개 시험 문제를 준비했습니다. 같은 작업을 요청하는 영어 표현 4개에 각 4개 파일을 배정했습니다. 각 문제를 두 이름 표기와 세 모델에서 실행해 **16×2×3=96회**를 측정했습니다. 이 새 응용시험을 **A1**이라고 부릅니다.

| 모델 | 원래 이름 V1: 성공 /16 | 바꾼 이름 V2: 성공 /16 | 둘 다 성공 | 성공→실패 | 실패→성공 | 둘 다 실패 |
|---|---|---|---|---|---|---|
| BF16 | 15/16 | 16/16 | 15 | 0 | 1 | 0 |
| RTN | 16/16 | 16/16 | 16 | 0 | 0 | 0 |
| D16 | 12/16 | 12/16 | 12 | 0 | 0 | 4 |

성공은 금액이 맞는 것뿐 아니라 필요한 결과를 받은 뒤 실제 저장·확인을 끝낸 경우입니다. 이름 변경으로 실패한 사례는 없었고 BF16에서 1개가 실패→성공으로 바뀌었습니다. D16은 두 이름 표기에서 같은 4개 문제를 끝내지 못했습니다.

## 구현한 기능

1. 기능은 유지하고 도구 이름만 바꾸며, 실제 동작이 같은지 검사합니다.
2. 각 응답을 만들기 전에 AI가 어떤 결과를 받았는지 기록합니다.
3. 저장된 응답을 새 실험용 파일에 다시 실행해, 실제 상태와 성공·실패를 재계산합니다.

## 기존 연구와의 연결

이전 단계 **P1**은 기존 8개 문제에서 이름·순서를 네 방식으로 바꾼 별도 시험입니다. 모델 3개와 조합한 96회에서 양자화 모델의 추가 민감도를 비교한 차이는 +8.33퍼센트포인트였고, 95% 구간 [-8.33,+25.00]이 0을 포함해 불확정입니다. A1과 문제·성공 기준이 달라 성공률을 합산하지 않습니다.

| 기존 P1의 작업 | AI에게 요구한 일 | 원 문제 ID |
|---|---|---|
| 문서 읽기 | 문서에서 장소 이름과 담당자 정보를 읽어 답하기 | AGENT-0/1 |
| 조회 후 계산 | 기록에서 개수와 개당 가격을 읽어 곱셈 도구로 총금액 계산하기 | AGENT-2/3 |
| 최신 정보 찾기 | 이전·현재 상태 표에서 최신 상태를 찾아 답하기 | AGENT-4/5 |
| 설정 수정·확인 | 실험용 설정 파일의 두 값을 바꾸고 확인 도구 실행하기 | AGENT-6/7 |
