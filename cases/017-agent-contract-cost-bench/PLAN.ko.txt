Case017 — Agent Contract–Cost Bench

목적: 같은 BF16 가중치의 Qwen3-4B에서 도구 호출 계약과 native KV 정밀도를
바꾸었을 때 실제 상태·검증·최종 답의 완주율과 비용이 어떻게 달라지는지 측정한다.

사용자 지시는 0~5절까지 전달되었다. 그 안의 출력 계약·예산·데이터 분리를
그대로 적용하고, 다음 실행 순서와 분석 세부는 이번 로컬 사전 등록으로 추가했다.
뒤에 전달되지 않은 절을 읽었다고 가정하지 않는다.

P0: 실제 BF16/NVFP4 캐시·36층 attention 유한성·원생성 관측·서버 문법 제약 확인.
    별도 smoke는 DEV/HOLDOUT 성공률 분모에서 제외. 최대 모델 요청 32회.
P1: DEV8 × KV2 × 정책4 = 64개 자유 episode. 한 번씩 실행한다.
P2: P1 완료·코드 동결 확인 뒤 HOLDOUT24를 생성·봉인하고 192개 episode 실행.
P3: COST6의 fixture/정답 경로만 준비한다. GPU 측정은 이번에 하지 않는다.

GPU worker 누적 상한은 운영상 7,200초로 등록했다. 로드·컴파일·실패·I/O를
포함하며 GPU busy 시간이나 serving latency가 아니다. 남은 예산이 episode와
정상 종료를 보장하지 못하면 PARTIAL과 누락 목록을 남긴다.

정책 C0/G/N/E는 동일 endpoint·template·단일 JSON·엄격 parser를 사용한다.
G만 공개 schema의 structured decoding을 매 응답에 적용한다. 설치 backend의
uniqueItems 미지원은 GPU 이전에 확인했으므로 해당 조건은 모든 정책의 host
검사에만 남긴다. 축소 범위는 specs/protocol.json과 grammar schema에 등록했다.
N/E는 첫 계약 실패에만 한 번, 정상 업무 오류에는 별도 재시도하지 않는다.

final도 6회 action 예산을 소비한다. 여섯 번째가 final이면 허용하고,
여섯 번째가 다른 행동이면 실행 후 종료한다. 추가 final의 가상 성공을 만들지 않는다.

모든 값은 raw 응답·사건·새 fixture 재생과 별도 endpoint 계산으로 확인한다.
합성 계약 검사는 모델 실측과 분리한다. E-N은 독립 자유 정책의 비교이며
오류 문구 정보만의 인과효과로 해석하지 않는다. 구간은 가족별 task 재표집의
탐색적 pointwise 구간이며 일반 업무 모집단·동등성 보장이 아니다.

기존 8,950개 tracked 파일과 Case015/016의 과학적 기록은 보존한다.
이번 종료점은 로컬 코드·원자료·CPU 재현·한영 보고서·검토 ZIP이다.
Git stage/commit/push/PR/merge, Pages/Drive 배포는 실행하지 않는다.
