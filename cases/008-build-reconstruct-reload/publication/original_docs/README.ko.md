# Case 008 — 모델을 변환·보정하고 다시 실행하기

[English](README.md) | 한국어

Qwen3-4B-Instruct-2507의 GPTQ W4A16 저장본과 Qwen3-0.6B의 13번 층 MLP를 축소·보정한 독립 저장본을 만들었습니다. 두 트랙 모두 다른 디렉터리에서 새 프로세스로 다시 불러왔습니다. W4 safetensors 크기는 2,651,839,568바이트로, BF16 원본의 8,044,982,000바이트와 비교했습니다. R은 작은 down projection만 적합했을 때 미관측 입력 192개의 원래 BF16 출력 오차가 얼마나 회복되는지 평가합니다. 모델과 실행기가 다르므로 두 트랙의 품질·비용을 따로 보고합니다.

## Q: 압축 가중치를 실제 실행기로 연결

RTX 5080에서 252개 Linear 모듈을 GPTQ W4A16, 대칭 group 128로 변환했습니다. 임베딩·정규화·출력 head는 BF16으로 남깁니다. 별도 고정 변환 환경이 compressed-tensors 저장본을 만들고, 기존 vLLM 환경이 Marlin 커널로 실행합니다. 두 재로딩 프로세스에서 smoke 점수와 짧은 greedy 생성 token이 일치했습니다. 가중치 바이트, 할당기 메모리, 요청 시간은 각각 다른 측정 범위입니다.

| 설정 / 입력 192개 | 정답 수 | Δ 전체 어휘 정답 NLL (nats; 95% 구간) |
| --- | ---: | --- |
| Q-BF16 | 137/192 | +0.000000 [+0.000000, +0.000000] |
| Q-W4 | 137/192 | -0.591295 [-0.723442, -0.470060] |

정답은 생성 규칙으로 별도로 계산합니다. NLL 변화는 후보−BF16이며 양수일수록 정답 token에 준 확률이 낮아진 방향입니다. 네 선택지 안에서 정규화한 NLL 변화는 +0.379465 [+0.248205, +0.497079] nats로 악화 방향입니다. 선택지에 할당된 전체 어휘 확률질량의 평균은 BF16 0.666963, W4 0.673368였습니다. 전체 어휘 NLL과 조건부 선택 NLL이 반대 방향으로 움직였으므로 같은 정답 수만으로 결과를 요약할 수 없습니다. 짧은 합성 조회·비교·정수 프로그램 입력의 결과로, 일반적인 언어 품질을 대표하지 않습니다. 정답 손실·개선·오답 간 변경과 과제별 기준 성능은 [상세 분석(영어)](ANALYSIS.md)에 있습니다.

![Q의 정답 NLL 변화와 입력별 재표집 구간. 양수는 악화 방향입니다.](figures/q_score_boundaries.png)

## R: 작은 행렬 크기를 유지하며 출력 가중치 적합

Case 007의 I25/P25/S50 삭제 집합을 그대로 사용합니다. gate/up의 행과 down의 열을 실제로 제거하고, DEV에서 고른 공통 ridge 강도 η=0.01로 남은 down 가중치만 적합합니다. 추론은 BF16이며, 보정 전후 shape·parameter 수·행렬 곱 개수는 같습니다.

| 고정 구조 | 오차 에너지 회복률 (95% 구간) | 국소 오차가 줄어든 입력 |
| --- | ---: | ---: |
| I25 | 95.40% [95.25, 95.55] | 192/192 |
| P25 | 94.96% [94.79, 95.13] | 192/192 |
| S50 | 94.09% [93.90, 94.28] | 192/192 |

회복률은 입력마다 고정한 32개 위치에서 삭제로 생긴 **제곱 출력 오차 에너지**가 줄어든 비율입니다. 정확도 향상률이 아닙니다. 구간은 192개 입력을 재표집하며, 그 안의 6,144개 위치를 독립 표본으로 늘리지 않습니다. R-B는 원래 모델이고 나머지 여섯 설정은 세 삭제 구조의 보정 전후입니다.

![R의 세 고정 구조에서 보정으로 회복한 출력 오차 에너지 비율입니다.](figures/r_recovery.png)

| 설정 / 입력 192개 | 정답 수 | Δ 전체 어휘 정답 NLL (nats; 95% 구간) |
| --- | ---: | --- |
| I25 | 128/192 | -0.583823 [-0.660297, -0.505045] |
| I25-R | 124/192 | -0.058966 [-0.082720, -0.034713] |
| P25 | 130/192 | +0.774289 [+0.727695, +0.820419] |
| P25-R | 123/192 | -0.134708 [-0.155610, -0.113348] |
| R-B | 124/192 | +0.000000 [+0.000000, +0.000000] |
| S50 | 107/192 | +2.267479 [+2.169380, +2.371095] |
| S50-R | 122/192 | -0.139956 [-0.173521, -0.106027] |

보정 전 대비 전체 어휘 정답 NLL의 평균 변화는 I25 +0.524857 nats(악화), P25 −0.908996, S50 −2.407435(개선)였습니다. 정답 수는 각각 128→124, 130→123, 107→122로 바뀌었습니다. 두 모델의 코드 과제 기준 성능은 모두 16/64로, 이 과제의 실용적 수행력에 관한 해석은 제한됩니다. 원래 모델의 계산을 보존하는 것과 별도 정답에 좋은 점수를 주는 것은 서로 다른 평가입니다. 배포 판정은 **NOT_ASSESSED**로 유지하며 품질 동등성이나 보편적인 허용 기준을 적용하지 않습니다.

## 측정한 요청 비용

| 토큰화가 끝난 Q 요청 | BF16 / W4 평균 ms | BF16 / W4 속도비 [95% 구간] |
| --- | ---: | --- |
| fixed_8_token_request | 164.711 / 150.969 | 1.0910 [0.8790, 1.2899] |
| one_token_request | 21.638 / 23.329 | 0.9275 [0.8474, 1.0095] |

Q는 sampling·스케줄링·결과 반환을 포함한 로컬 vLLM 요청입니다. 두 속도비 구간 모두 1을 포함합니다. 두 설정의 KV cache 할당은 1 GiB로 고정했습니다. 가중치 파일이 작아진 것만으로 요청 시간이 줄었다고 해석할 수는 없습니다.

| 같은 크기의 보정 전후 | Prefill + argmax 속도비 [95% 구간] | 고정 8-token 요청 속도비 [95% 구간] |
| --- | ---: | --- |
| I25 | 0.9678 [0.8668, 1.0718] | 1.0295 [0.9727, 1.0905] |
| P25 | 1.0450 [0.8942, 1.2265] | 1.0088 [0.9609, 1.0598] |
| S50 | 0.9313 [0.8329, 1.0374] | 0.9981 [0.9631, 1.0328] |

R의 속도비는 같은 작은 행렬 폭에서 보정 전 시간 / 보정 후 시간이며 1보다 크면 보정 후가 빠른 방향입니다. 각 트랙은 고정 입력 12개·프로세스 3회차·대응 블록을 사용합니다. 서로 다른 실행기의 속도비를 합치지 않습니다. 설정별 시간과 메모리 측정 범위는 [상세 분석(영어)](ANALYSIS.md)에 있습니다.

## 확인과 실행

[기존 기록 탐색기(영어)](demo/index.html)는 과제·입력 ID·설정으로 결과를 고르고 JSON을 내려받는 로컬 HTML입니다. GitHub의 HTML 원문 보기와는 다릅니다. [재현 안내(영어)](REPRODUCTION.md)는 CPU 재계산, 비공개 모델 저장본 검사, GPU 재로딩과 비용 측정을 구분합니다. 모델 가중치·전체 hidden·어휘 벡터는 검토 묶음에 포함하지 않습니다.
