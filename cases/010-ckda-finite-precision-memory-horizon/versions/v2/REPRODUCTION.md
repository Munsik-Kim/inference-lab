# Reproduction paths and boundaries

Run these commands from this case directory, `research/case010-failure-aware-v2/`. Replace the uppercase path placeholders before running them. Use new output locations; completed observations and checkpoint directories must not be overwritten.

The three paths below have different requirements. The delivered v2 package contains this new study and the unchanged v1 source copies identified in [v1 source identities](provenance/v1_source_identity.json). The original 30.9 MB v1 review ZIP, trained model checkpoints, full hidden-state histories, and upstream checkout are separate inputs and are not bundled in v2.

Use an existing compatible environment. No package installation or upgrade was performed for this study; its observed versions are recorded in [environment.json](provenance/environment.json). NumPy suffices for the independent scalar auditor and synthetic byte-codec tests. Historical figure generation also needs Matplotlib. Model/runtime and precision tests require CPU PyTorch; tests that construct the original CKDA model also require the pinned upstream checkout and its compatible existing dependencies.

```bash
export CPU_PATH=/PATH/TO/EXISTING_ENV/bin/python
export PRIVATE_RUN=/PATH/TO/NEW_PRIVATE_REPRODUCTION
export PYTHONDONTWRITEBYTECODE=1
export CUDA_VISIBLE_DEVICES=
export OMP_NUM_THREADS=2
export MKL_NUM_THREADS=2
export MPLCONFIGDIR="$PRIVATE_RUN/matplotlib-cache"
mkdir -p "$PRIVATE_RUN"
```

`PRIVATE_RUN` is for receipts, logs and private resumable state, outside the public result tree. No command below trains a model or enables a GPU.

## 1. Model-free audits of delivered observations

The [independent v2 auditor](analysis/audit_v2.py) reconstructs first failure, RMST0, all-token empirical horizons, grid counts and token accuracy from retained predictions versus gold. It checks packed correctness, terminal suffixes, frozen input identities, the 195-comparison confidence family, the serialized 17-byte header, and actual initial-cache/shared artifact lengths. Clopper–Pearson endpoints are checked with an independent finite-binomial sum; SciPy and the model are not required.

Once all 15 fresh cells are present:

```bash
"$CPU_PATH" -B analysis/audit_v2.py \
  --results results/fresh \
  --output "$PRIVATE_RUN/fresh-scalar-audit.json"
```

The receipt must be outside the audited results directory and must not already exist. Missing or incomplete cells cause failure. For an explicitly partial inspection, add `--allow-partial`; a subset is reported as `INCOMPLETE`, never a full-study `PASS`.

The [aggregation tool](analysis/aggregate_v2.py) requires all 15 cells and a passing independent audit. It verifies the frozen metric source before calling the original `paired_summary`, with 5,000 repeats and seed `60101 + 100 * model_seed + pair_index`. The three declared pairs are reported separately for every model seed.

```bash
"$CPU_PATH" -B analysis/aggregate_v2.py \
  --results results/fresh \
  --output "$PRIVATE_RUN/fresh-summary"
```

It creates `fresh_table.csv`, `paired_table.csv`, `bytes_table.csv`, `combined.json` and `source_hashes.json` in the new output directory. This operation is only valid after the full 15-cell experiment is complete. Pointwise paired intervals do not become simultaneous superiority tests, and diagnostic or historical sequences never enlarge fresh N=1,024.

## 3. Bounded inference with the three fixed checkpoints

This path additionally requires all three private checkpoint files and a compatible clean checkout of ComplexKDA at `ef9d108d1692387cae37f5b2d539a71826a127c1`. Loaders verify the checkpoint SHA256, required upstream source bytes, strict model state and exact retained FP32 token coefficients. The files remain private and are not uploaded or copied into the public result tree.

```bash
export CKDA_CHECKPOINT_0=/PATH/TO/PRIVATE/seed0/final.pt
export CKDA_CHECKPOINT_1=/PATH/TO/PRIVATE/seed1/final.pt
export CKDA_CHECKPOINT_2=/PATH/TO/PRIVATE/seed2/final.pt
"$CPU_PATH" -B - <<'PY'
import hashlib, json, os
from pathlib import Path
protocol = json.loads(Path('protocol_v2.json').read_text())
for seed in range(3):
    path = Path(os.environ[f'CKDA_CHECKPOINT_{seed}'])
    actual = hashlib.sha256(path.read_bytes()).hexdigest()
    assert actual == protocol['checkpoint_sha256'][str(seed)], f'Wrong checkpoint seed {seed}'
    print(f'checkpoint seed {seed}: SHA256 verified')
PY
export RUN_DEADLINE_EPOCH="$("$CPU_PATH" -c 'import time; print(time.time()+14400)')"
```

Use a new result branch within this case, such as `results/reproduction-fresh/`; the fresh runner records case-relative paths for its public initial-payload sample. Do not point it at the retained `results/fresh/`. A complete fresh replication is the fixed three-seed by five-arm set, with N=1,024 and T=2,048 for every cell:

```bash
for STUDY_SEED in 0 1 2; do
  case "$STUDY_SEED" in
    0) STUDY_CHECKPOINT="$CKDA_CHECKPOINT_0" ;;
    1) STUDY_CHECKPOINT="$CKDA_CHECKPOINT_1" ;;
    2) STUDY_CHECKPOINT="$CKDA_CHECKPOINT_2" ;;
  esac
  for STUDY_ARM in NATIVE_FP32 UNIFORM_8 UNIFORM_5 LOWRANK_4_8_R2 MIXED_5_6_BUDGET; do
    "$CPU_PATH" -c 'import os,time,sys; sys.exit(0 if time.time()<float(os.environ["RUN_DEADLINE_EPOCH"]) else 1)' || break 2
    "$CPU_PATH" -B -m source.run_fresh \
      --seed "$STUDY_SEED" --arm "$STUDY_ARM" \
      --checkpoint "$STUDY_CHECKPOINT" --upstream "$CKDA_UPSTREAM" \
      --output "results/reproduction-fresh/seed$STUDY_SEED/$STUDY_ARM" \
      --private-output "$PRIVATE_RUN/fresh/seed$STUDY_SEED/$STUDY_ARM" \
      --deadline-epoch "$RUN_DEADLINE_EPOCH" || break 2
  done
done
"$CPU_PATH" -B analysis/audit_v2.py \
  --results results/reproduction-fresh \
  --output "$PRIVATE_RUN/reproduction-fresh-audit.json"
```

The deadline is cooperative at the declared checkpoint boundaries 256/512/1,024/1,536/2,048. A running chunk can finish beyond the deadline; a partial result is not counted as completed. Fresh `elapsed_seconds` after resume describes the current attempt's suffix, not a reconstructed full-call benchmark. Resume with the same cell identity, output roots and newest completed private checkpoint, for example:

```bash
"$CPU_PATH" -B -m source.run_fresh \
  --seed 0 --arm NATIVE_FP32 \
  --checkpoint "$CKDA_CHECKPOINT_0" --upstream "$CKDA_UPSTREAM" \
  --output results/reproduction-fresh/seed0/NATIVE_FP32 \
  --private-output "$PRIVATE_RUN/fresh/seed0/NATIVE_FP32" \
  --resume "$PRIVATE_RUN/fresh/seed0/NATIVE_FP32/offset-0256" \
  --deadline-epoch "$RUN_DEADLINE_EPOCH"
```

Only use an actually existing completed checkpoint and an incomplete cell. Resume remains subject to the original total resource cap; an expired cap is not reset by this example. The evaluation-job checkpoint carries cumulative predictions, gold prefix, first-failure history, sample IDs and counts separately from the charged model cache. Its same-filesystem rename provides atomic visibility; it is not a promise of fsync durability. A technical interruption requires an explicit attempt record, never an outcome-driven rerun or silent overwrite.

Full recurrent state/logit histories are not retained publicly.

Run timing only after other study workers have stopped, serially across seeds. The command itself has no deadline flag; launch its fixed bounded workload only within the remaining global cap:

```bash

  --seed 0 --checkpoint "$CKDA_CHECKPOINT_0" --upstream "$CKDA_UPSTREAM" \

```

Timing covers the CPU complete call for 16 inputs × 128 group tokens, three repeats per arm, with one four-token warmup per arm. Loading, gold/shadow diagnostics and file I/O are outside the timer. BOS work is included in the call while the rate denominator is group tokens. These prototype measurements are not GPU speed or single-request latency.

### Actual historical failure-boundary appendix

The 19 main historical replay cells do not by themselves exercise a fresh process immediately after every selected failure. The [separate boundary runner](source/run_failure_boundaries.py) uses the delivered [frozen appendix](provenance/historical_failure_boundaries_v1.json) and its adjacent `.sha256` to replay four already-observed cases, including the Uniform3 failure after the main replay's last interior cut. This is continuation-contract coverage, not a new memory trial.

This command additionally requires the complete private historical replay tree for all three seeds. `--historical-private` is the parent of the `seed0/`, `seed1/` and `seed2/` directories produced by the full `source.run_historical` runs above, or the original matching private tree. Preserve its input arrays, worker plans, serialized checkpoint bodies and final runtime bytes. These files are not shipped in the review package, and public hashes or compact predictions cannot replace them. The runner reads the worker plan and its referenced input path plus the `parent-checkpoints/cut-0001` checkpoint; their identities must match the retained public historical receipts. If using a recreated tree, finish all three historical runs first and keep their recorded private input paths valid.

Unlike the other runners, this runner takes a checkpoint root with the exact layout `training-seed0/final.pt`, `training-seed1/final.pt`, `training-seed2/final.pt`. They must be the same three verified checkpoint files. Keep that root private. With the historical commands above, use:

```bash

"$CPU_PATH" -B -m source.run_failure_boundaries \
```

Use new output directories and the same remaining deadline. The delivered appendix already freezes the selected cases and reference hashes; do not pass `--freeze` or replace its reference receipts to make a failing replay pass. A successful run writes four compact public receipts and an `index.json`; full serialized state bodies and fresh-process work remain in the private output tree.

## Frozen sources, attribution and preservation

[protocol_v2.json](protocol_v2.json) and the [71-file freeze inventory](provenance/protocol_freeze.json) fix the design, inputs, coefficients, codecs and critical runtime. `verify_protocol()` checks their hashes before actual inference. Orchestration and reporting code are outside that original critical-file inventory; their execution identities are recorded separately in [fresh attempt records](provenance/fresh_attempts.jsonl), [diagnostic attempt records](provenance/diagnostic_attempts.jsonl), and runner receipts. A reproduction should also preserve the hashes of the exact runner files it executes.

The public initial zero-cache sample demonstrates fixed serialized row size. The final cache hash and length do not expose or replace the private final hidden-state body. Checkpoint weights, real resumable job directories and model-state tensors stay outside the public package. Original v1 sources, archive and upstream files are never edited by these commands. See [NOTICE](NOTICE.md) and [CHANGELOG](CHANGELOG.md) for attribution and implementation scope.
