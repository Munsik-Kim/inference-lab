# CKDA Finite-Precision Memory Horizon

[English](README.md) | 한국어

반복 상태를 저비트로 저장하고, 잔차 보정과 실제 저장량을 비교하는 도구를 구현했습니다. 각 입력에서 정확한 기호 상태를 처음 잘못 읽은 시점을 확인하고, 판독 유지 곡선을 재계산하며, checkpoint와 직렬화한 상태로 실행을 이어갈 수 있습니다.

질문은 **같은 총 저장 바이트에서 고정된 모델이 올바른 상태를 더 오래 판독하는가**입니다. 상태의 평균제곱오차가 작거나 마지막 답만 맞았다는 결과와 구분해 측정합니다.

## 구현한 기능

- [실제 비트 단위 저장](codec/packed.py): 저비트 코드, FP32 scale, padding, 확률적 반올림의 난수 상태를 바이트로 담습니다.
- [온라인 잔차 보정](codec/online.py): 후보가 자기 상태를 저장하면서 잃은 값만 보정하고, 다음 상태 전이에서 잔차도 함께 변환합니다. 전체 잔차와 CAL에서 고정한 rank1/2/4 basis의 비용을 각각 계산합니다.
- [작은 학습 S3 CKDA 비교](scripts/evaluate_learned.py): 같은 모델의 원래 판독기를 사용해 모든 token과 head에 개입합니다. 균일2–16비트와 CAL 기반 혼합 정밀도도 같은 저장 한도에서 비교합니다.
- [최초 실패와 관측 종료 처리](codec/survival.py): 나중에 다시 맞혀도 처음 틀린 시점은 유지합니다. [새 프로세스 재시작 검사](scripts/check_restart.py)는 저장한 상태만으로 이어지는지 확인합니다.

## 읽는 순서

[한국어 보고서](REPORT.ko.md)에 가설, 실험 설계, 결과와 결론을 정리했습니다. [방법론 원문(영어)](METHODS.md)은 상태 전이, 판독 경계, 저장량의 정의를 설명합니다. [재현 안내(영어)](REPRODUCTION.md)는 모델 없이 하는 CPU 검산, checkpoint 실행, GPU 학습을 나눠 안내합니다.

학습 없는 다섯 가지 수치·기하 대조와 학습 모델의 결과는 분리했습니다. 학습 모델은 공식 S3/a11_b02 구조로, 한 층·12개 head·head당 16×16 상태·56,530개 매개변수를 사용합니다. 세 seed를 같은 20,000회 갱신 계획으로 학습했고, 각 seed의 모든 codec은 같은 가중치를 사용합니다. 주 평가는 설정마다 512개의 독립 입력을 길이 2048까지, 매 단계의 누적 상태에서 판독합니다.

저장 장부에는 공유 설정·token 계수 표·basis와 입력별 코드·scale·잔차·난수 상태·진행 위치를 합산합니다. 동시 입력 1·16·128개에서의 총량을 제공합니다. 모든 설정이 공유하는 checkpoint는 별도 기록하며, 상태 저장량을 모델 전체 VRAM으로 표현하지 않습니다.

## 실제 관측

세 native 모델 모두 동시 신뢰구간에서 최초 실패 위험5% 이하의 판독 길이 하한64 group token을 지지했습니다. 그러나 길이1024까지 모든 TEST 입력에서 한 번 이상 오답이 나왔습니다. 저정밀 저장의 효과와 native 모델 자체의 길이 외삽 한계를 함께 볼 필요가 있습니다.

같은 저장 한도에 들어가는 혼합 정밀도 네 배분을 추가하면, **잔차 설정의54개 예산 비교에서 지지되는 판독 길이가 가장 좋은 허용 비교군보다 긴 경우는 없었습니다.** rank2 보정은 N=128에서 세 seed 모두 평균 연속 정답 길이를 늘렸지만 주 지표와는 다릅니다. 추가 배분은 같은 TEST를 재사용한 사후 예산 검사입니다. [전체 결과와 해석](REPORT.ko.md#결론).

![세 학습 CKDA checkpoint의 최초 판독 실패 누적 비율](figures/learned_first_failure.png)

원래26개 설정 연구의 곡선입니다. 세 모델 seed가 각각512개 입력을 판독했으며 점선은 관측 실패 비율5%이고 신뢰구간 상한이 아닙니다. [원래 곡선 데이터](results/summary/horizon_curves.csv) · [보충 설정을 포함한 예산 비교](results/supplement-summary/budget_comparisons.csv).

실제 packed 상태는 새 프로세스 재시작 검사를 통과했습니다. CPU의 저장·전이·복원·판독 경로는 native보다 느렸습니다. 이번 구현은 저장량과 판독 유지 여부를 확인하는 도구이며 fused kernel 가속 결과는 아닙니다.

## 기여와 출처

DIOVA는 비트 단위 상태 저장, 잔차 adapter, 재시작 검사, 최초 실패 분석과 통제 비교를 구현했습니다. 모델·과제·optimizer는 Complex KDA의 구현을 사용했습니다. 잔차 feedback과 상태 혼합 정밀도의 선행연구 대응 및 Codex 지원은 [출처 안내(영어)](NOTICE.md)에, 순차 prototype과 작은 모델의 적용 범위는 [한계(영어)](LIMITATIONS.md)에 정리했습니다.

이 디렉터리는 로컬 검토 후보입니다. checkpoint는 별도의 로컬 자료로 보관하며, 이 패키지에는 코드·간결한 관측 기록·검산 도구를 담습니다.
