FEATURED B · DIOVA-COMPARE · SYNTHETIC CPU EXAMPLE

Compare answers on the same questions

The tool I built takes two saved answer files and reports which questions became wrong, became correct, or received different answers.

Use it to review a model change or compression. Run models and grade their outputs first. It compares saved results; model execution, general free-form grading and source authentication are outside its scope. These four hand-authored synthetic_test pairs are not GPU measurements or evidence of model performance.

1. Prepare two files → check format (validate) → compare

Before-change results (baseline JSONL) · After-change results (candidate JSONL). JSONL is a text format with one question’s result per line. From the repository root, use Python 3.10+ with fresh environment/output paths:

EXAMPLE_ROOT=$(mktemp -d)
python3 -m venv "$EXAMPLE_ROOT/venv"
"$EXAMPLE_ROOT/venv/bin/python" -m pip install --no-deps ./packages/diova-compare
"$EXAMPLE_ROOT/venv/bin/diova-compare" validate --input packages/diova-compare/examples/compare/baseline.jsonl
"$EXAMPLE_ROOT/venv/bin/diova-compare" validate --input packages/diova-compare/examples/compare/candidate.jsonl
"$EXAMPLE_ROOT/venv/bin/diova-compare" compare --baseline packages/diova-compare/examples/compare/baseline.jsonl --candidate packages/diova-compare/examples/compare/candidate.jsonl --output "$EXAMPLE_ROOT/report"

Expected: PASS with 4 records for each validation, PASS with 4 pairs for comparison, exit 0. PASS means the input check and comparison completed; it does not mean all answers were correct. Generates report.md, report.json and pairs.csv. No model, Torch, CUDA or NumPy is needed; installation may fetch Python build tools. Shell paths above are Linux/macOS; Windows can use the same CLI arguments in a separate Python environment.

2. Equal accuracy can hide a newly wrong answer

The accepted correct answer (gold) is the arithmetic sum, defined independently of either model’s answer. Answers are whitespace-stripped decimal integer strings.

Four synthetic pairs; separate from measured model results
ID / questionGoldBaseline → candidateTransition
sum-01 / 2 + 244 → 5Lost correct answer
sum-02 / 3 + 587 → 8Gained correct answer
sum-03 / 6 + 176 → 9Different wrong answer
sum-04 / 4 + 599 → 9Both correct

Both score 2/4. The report separates lost correct answers (correct_to_wrong=1), gained correct answers (wrong_to_correct=1), changed wrong answers (wrong_to_wrong=1), and all changed answers (all_answer_disagreement=3). Use report.md for the task summary, report.json for configuration and all pairs, pairs.csv for individual changes. Four synthetic pairs and their descriptive intervals do not rank real models.

3. Map your own saved records

Prepare results from two model settings, accepted correct answers, and the rules used to extract and grade each answer. For free-form text, you supply the correct/incorrect judgment. Then validate each file and compare them.

Saved results → input format (schema version 1)
SourceFields
Dataset / version / item keytask, task_version, sample_id
Exact shared input ruleprompt_hash: SHA256 of UTF-8 input, including system/template text under the same rule
Accepted correct answers (gold) and gradinggold, gold_definition: identical accepted strings and extraction/normalization rule
Model / saved model file (checkpoint) identitymodel_id, artifact_id: one combination per file
Extracted answer / caller gradingoutput_type: extracted_answer, answer, boolean correct
Provenance / formatevidence_kind: measurement / historical / synthetic_test; integer schema_version: 1
Optional source statusprocess_exit_code: integer on all rows of both files, or omitted throughout

Compute hashlib.sha256(prompt.encode("utf-8")).hexdigest(). The CLI compares identifiers, without authenticating actual questions or saved model file contents (artifact bytes). Free-form correctness is user-supplied, not automatic grading.

For basic answer comparison, omit distribution and scores. Probabilities for all vocabulary entries or raw model scores (logits) are not required. Optional choice probabilities allow loss checks (NLL and Brier); compatible distributions allow a difference-from-original check (KL). Validate each file, then replace the compare input paths. Keep private inputs out of shared reports. There is no browser upload step.

4. Reject different questions or gold rules

Changing only the first candidate prompt_hash to "0" * 64 gives pair mismatch: prompt_hash, exit 2, with no report directory. Changing gold_definition gives pair mismatch: gold_definition. Each file may validate alone while pairing fails. The --intersection option does not repair a changed input contract.

5. Why it works this way, and its limits

  • Chosen: match the same questions and separate lost answers, gained answers and changed answers and retain source failure status.
  • Alternative: mean accuracy alone hides the example’s previously correct answer becoming wrong.
  • Evidence: core and contract tests.
  • Limit / next criterion: users must check that the grading and question identification rules suit their task. This describes the current design, not another historical alternatives experiment.
