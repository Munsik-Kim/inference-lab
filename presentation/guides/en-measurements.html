How to read the measurements

Smaller files, faster requests and correctly completed work are separate outcomes. Each needs its own check. Complete explanation in Korean. Definitions for existing research terms remain in the shared glossary.

Files and GPU memory

Weight file bytes measure disk storage. Torch allocator peaks record the most memory allocated for active calculations by PyTorch’s memory manager. Whole-device sampled peaks include other processes and can miss short spikes. GB = 10⁹ B, GiB = 2³⁰ B, MiB = 2²⁰ B. Do not exchange these scopes or units.

Waiting, generation and completion

TTFT is the wait for the first response (the first answer chunk, or choice SSE, in Case009). A token is a piece of text processed by the model. TPOT measures time per subsequent output token. Output throughput divides total output tokens by the measurement interval and can include concurrent requests. Full request latency includes preparation, waiting, generation and transport.

Fixed-length timing matches input/output lengths and simultaneous request limits. Free-form answer checks use separately defined correct answers (gold), answer extraction rules and an output length limit. Shorter output can finish sooner without faster token generation.

Agreement, accuracy and actual work

Matching the original model’s answer (agreement) and matching an independently defined correct answer (accuracy) answer different questions. For tool work, check executed actions and the expected test file state (fixture), as well as the final success message. A saved compressed file also needs a separate execution check: comparison calculations (reference) may restore values to the 16-bit BF16 format before multiplying them.

Evidence and execution states

Keep direct measurements, reanalysis of saved records and theoretical calculations distinct. A policy-skipped run is unexecuted, not an observed out-of-memory error. Abnormal process finalization after saved calculations is a process failure. A clean execution can still turn previously correct answers into wrong ones (regressions).

Repetitions do not add independent tasks

Eight tasks repeated under ten conditions produce 80 execution records (episodes), with only eight different tasks. Rerunning tasks used during development (DEV) does not test new tasks withheld from that development (held-out). Case009’s intervals resample three server comparison rounds; each round pairs the original and compressed model under the same conditions.

Preserve the execution boundary

Case013 checks quality by restoring values to BF16. Its full-model calculation check for direct compressed execution (packed) failed. Read quality and speed from the same tested way of running the model. Before applying a result, check the model name, version (revision), saved model files (artifact), running program, task conditions and whether the program exited normally.
