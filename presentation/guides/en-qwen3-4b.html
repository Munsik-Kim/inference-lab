Mitigating tool-name failures

D16 is a weight-only four-bit experimental reference variant. D4 additionally lowers activations. Registered-name constraints and differentiated error feedback were implemented without retraining. Actual fixture patch and validation events were checked, not just the final JSON.

{{repair_table}}

The same {{dev_tasks}} previously observed DEV tasks were reused. {{episodes}} episodes are {{logical_conditions}} conditions on those tasks, not {{episodes}} independent tasks. D4 retains {{d4_remaining}} failures. Enum and both tied, so an additional benefit from feedback on top of enum was not established.

This is system mitigation on this reference variant. It establishes neither quantization-error recovery nor generalization, all-INT4/DualQuant quality or packed serving speed. Candidate 32K tests were skipped by memory policy, not observed OOMs.

Technical judgment — current design

  • Chosen: separate constraints, feedback and both; check final JSON against executed edits and validation.
  • Alternative: JSON-only grading misses claimed success without an action.
  • Evidence: the recorded conditions, linked guard, event analysis and tests. Enum and both tied; added feedback benefit was not established.
  • Limit / next criterion: retain reused DEV scope and remaining D4 failures; new tasks and registry contracts require separate evaluation.

Implementation and attribution

The project connected artifact validation/reload, matched serving/quality runners, reference codecs/adapters, constrained tool-name decoding and event auditing. Qwen, GPTQ, LLM Compressor, compressed-tensors, safetensors, PyTorch, Transformers, vLLM and Marlin provide the external model, methods, libraries and kernels. DualQuant is the research source for the explicitly bounded reference variant.
