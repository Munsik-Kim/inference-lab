Qwen3-4B: execution, quality and remaining failures

I built workflows to reduce model files and run them again, compare response time and answers, and investigate failed AI tool actions. This is a summary, not a complete translation. Read the full Korean guide for configuration-specific instructions, tables and provenance.

Mitigating tool-name failures

D16 stores learned weights as INT4 and restores them to BF16, with BF16 inputs to each calculation. D4 uses the exact same weights, additionally reduces calculation inputs to INT4, then restores them to BF16. They are two conditions of the same model. I built a restriction to registered tool names and clearer error guidance without retraining. Checks covered real edits to test files (fixtures) and successful validation records alongside the final JSON.

The same {{dev_tasks}} tasks used during development (DEV) were reused. The {{episodes}} execution records (episodes) cover {{logical_conditions}} conditions on those tasks, rather than {{episodes}} different tasks. D4 retains {{d4_remaining}} failures. Enum and both tied, so an additional benefit from feedback on top of enum was not established.

This is system mitigation on this reference variant. It establishes neither quantization-error recovery nor generalization, all-INT4/DualQuant quality or packed serving speed. Candidate 32K tests were skipped by memory policy, not observed OOMs.

Why it works this way, and its limits

  • Chosen: separate constraints, feedback and both; check final JSON against executed edits and validation.
  • Alternative: JSON-only grading misses claimed success without an action.
  • Evidence: the recorded conditions, linked guard, event analysis and tests. Enum and both tied; added feedback benefit was not established.
  • Limit / next criterion: retain reused DEV scope and remaining D4 failures; new tasks and different tool registration rules require separate evaluation.

Implementation and attribution

The project built saved-model checks and reopening steps, programs for comparing response speed and answers, code to save and restore four-bit numbers for quality checks, tool-name restrictions and checks of actual executed actions. Qwen, GPTQ, LLM Compressor, compressed-tensors, safetensors, PyTorch, Transformers, vLLM and Marlin provide the external model, methods, libraries and kernels. DualQuant is the research source for the explicitly bounded reference variant.
